2. **Dashboard poll** (`admin.js`): the silent 8-second refresh stands down only for an open `.card-more[open]`, a `dialog[open]` or a button in the grid being pressed (`grid.matches(':active')` — it reaches the grid while a card button is held, and clears on release; probe in `shots/FIX-C/proofs.txt`). `:hover` / `:focus-within` no longer block; instead `rememberGridFocus()` records the focused card's session id + the control's own class (or `summary` for the More button, `''` for the card) before every render and `restoreGridFocus()` puts focus back on the rebuilt node with `preventScroll` — on the card itself when the control vanished with the change (a Publish button after publishing). Applied to silent and non-silent loads alike. The stale comment on `adjustCardPhotoCount` was updated.
3. **Idempotent upload retries** (`admin.js`): `uploadAttemptMode(item, retrying)` — the crew's explicit `replace` / `rename` / `skip` always stands; otherwise any attempt after the item was first sent (an automatic retry after "Network dropped." / "Timed out." / a stall, an aborted stream after Stop, or a "Retry failed" / "Send n remaining" tap in a later batch) goes out as `onDuplicate=skip`. `item.attempted` is set right before the request so an abort mid-flight counts. `settleUploadResult()` turns a `{ skipped: true }` answer to such an attempt into a done result (`skipped: false, landed: 'earlier'`) because the only name it can match is the item's own earlier copy (the Add-photos dialog flags every name already in the session, so unflagged items are unique). The row shows "Sent", the batch counts it as sent, no thumb is re-posted (`photoId` absent). Deviation from the brief's literal "skip on every attempt > 1": an explicit `rename` is kept on retries — turning it into `skip` would silently drop the crew's "keep both" copy when the first attempt had *not* landed; the worst case with `rename` kept is a visible extra copy. `replace` is idempotent by itself.
4. **Re-auth Cancel** (`admin.html` + `admin.js`): `#reauthCancelBtn` (class `more-cancel`, 44 px, beside the submit inside the form so it moves with the panel into the Add-photos dialog). While a batch runs it takes the Stop path — `cancelUpload(reason)` now accepts the error to settle with — so in-flight streams abort, waiting ones stop, and the flow's own `finally` unlocks the form; during the pre-flight / create call (where the progress card's Stop is not on screen) it rejects the pending re-auth and the publish flow unlocks. Message: "Stopped — you are signed out. Sign in again when you are ready; nothing already sent is lost."
5. **Stale 401 after re-login** (`admin.js`): `apiRequest` and `uploadOne` remember the token a request went out with and attach it to the `unauthorized` error; `withReauth` and `uploadWithRetry` call `tokenRenewedSince(error)` and simply retry with the fresh token when the crew has already signed in again (a stream sent before the pause answers late), raising the panel only for a real expiry. When the panel is hosted on the Upload tab and that tab is not active, a toast "Paused — sign in again on the Upload tab" with an "Open the Upload tab" action (activates the tab without the title-focus, focuses the password field) is shown. Proof that the e2e test catches the old behaviour: `proofs/prove-stale-401.mjs` serves `admin.js` with `tokenRenewedSince()` forced false → the panel comes back a second time; the fixed file goes "Live" (`proofs.txt`).
6. **`runMoreUpload` and the moved panel** (`admin.js`): the dialog lock's `controls` list excludes `#reauthPanel` descendants, so a second pause inside Add photos (the panel is still in the dialog from the first) keeps its field and buttons enabled. E2E covers exactly that sequence.
7. **Lightbox `pointercancel`** (`app.js`): `finish()` returns before the flick maths on `pointercancel` — closes the drag state, clears the tap memory, resets `image.style.transform` when not zoomed (a zoomed pan is already committed by `apply()`). CDP-driven proof: a 60 px drag followed by `touchCancel` moved the old code to "3 of 9", the fixed code stays on "2 of 9"; a real lift after the same drag still turns the page (`proofs.txt`). Note: Chromium's own cancels (a scroll or system gesture claiming the touch) carry `clientX 0` as the reviewer said; CDP's `touchCancel` carries the last position — the old code advanced either way (60 px > the 40 px flick threshold), so the test distinguishes the fix regardless.
8. **`scrollTo({ behavior: 'instant' })` on old Safari** (`app.js`): the three call sites (`showResults`, `popstate`, the colour-search result) go through `jumpToTop()`: `try` the options form, `catch` → switch `documentElement.style.scrollBehavior` to `auto`, plain `scrollTo(0, 0)`, restore — so the jump is still instant where the enum value throws. Unit-tested against a fake `window` that throws on the options form.
9. **Decode upscaling** (`admin.js` + `preview-worker.js`): the decode width is now decided from the image header instead of the file size. `imageDimensions(bytes)` (a port of the Worker's migration-0012 parser: first JPEG SOF with EXIF orientation 5–8 swapping the axes — so it matches what `createImageBitmap` produces — PNG IHDR, WebP VP8/VP8L/VP8X) reads the first 64 KB once per `File` (`headerDimensions`, a WeakMap cache shared by the queue thumbnail and the preview); `decodeWidth(dims, size, max)` returns the fitted width only when the long edge exceeds the target (a portrait 3024 × 4032 decodes to 450 wide instead of 600-then-shrunk), `null` (natural size) otherwise, and falls back to the old "over 512 KB is a big frame" rule only when the header cannot be read (HEIC). The width travels with the job to the worker (`postMessage … resizeWidth`) and to the main-thread fallback; the worker no longer looks at `file.size` at all. Proof: the reviewer's case (a 500 × 500 PNG of 734 KB) — old worker decode sent `width=600&height=600` (37.5 KB preview), fixed sends `500 × 500` (28.2 KB) (`proofs/prove-upscale.mjs`, `proofs.txt`). Old admin.js + new worker, or new admin.js + old worker, both degrade to natural-size / size-rule decodes.
10. **Gallery link seam** (`app.js`): `galleryLinkParams(search)` accepts `?gallery=<id>.<token>` (the page's own share link and the Worker's new form) and `?gallery=<id>&token=<token>` (links minted before the switch); an explicit `token` param wins over a dot in the id; `resumeGalleryFromLink` drops the whole query first, then opens only a well-formed link. E2E opens the gallery cold from both spellings and confirms `?token=` alone is not a link.
