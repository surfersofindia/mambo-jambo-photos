Images, `soi-stamps.svg` and `.htaccess` are copied unhashed; source files keep their plain names so `npm run dev` and the tests are unaffected. Current output: 38 files, 12 fingerprinted, `index.html` scripts **18.3 KB gzip**, `admin.html` 29.5 KB gzip.

3. **`scripts/dev.mjs` (lead / dev-server owner):** gzip text responses so Lighthouse's `resource-summary` measures what production sends. Exact change — add `import { gzipSync } from 'node:zlib';` and replace the static-file response with:
   ```js
   const gzip = /\.(html|js|css|svg)$/.test(file) && /\bgzip\b/.test(request.headers['accept-encoding'] || '');
   const body = gzip ? gzipSync(content) : content;
   response.writeHead(200, { 'Content-Type': types[extname(file)] || 'application/octet-stream', 'Cache-Control': 'no-store', 'X-Content-Type-Options': 'nosniff', ...(gzip ? { 'Content-Encoding': 'gzip', Vary: 'Accept-Encoding' } : {}) });
   response.end(request.method === 'HEAD' ? undefined : body);
   ```
   Why: today `resource-summary:script:size` fails on 58,357 raw bytes although the page ships 18.3 KB gzip; with this the 40 KB assertion in `lighthouserc.json` measures the compressed budget the program actually set.
