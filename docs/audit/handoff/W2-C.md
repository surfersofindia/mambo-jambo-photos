## Tasks done (by id)

- **Migration 0012 · photo dimensions.** `ALTER TABLE photos ADD COLUMN width/height INTEGER`. Parser: `imageDimensions(bytes)` reads only header bytes — JPEG walks the marker chain (fill bytes and standalone markers stepped over, stops at SOS/EOI with `null`), takes the first SOF (C0–C3, C5–C7, C9–CB, CD–CF) and swaps width/height when an APP1 EXIF IFD0 orientation is 5–8 (both TIFF byte orders); PNG reads IHDR; WebP reads `VP8 ` (start code checked, 14-bit sizes), `VP8L` (14+14 bits + 1) and `VP8X` (24-bit canvas − 1). Anything else, zero sizes or a header cut short → `null`. Streaming path: the first 64 KB are copied aside inside the existing FixedLengthStream pump as chunks flow to R2 (`chunk.slice`, bounded at 64 KB, body never buffered) — **deviation from "a second TransformStream"**: R2 needs the FixedLengthStream's own readable, and piping it through another TransformStream drops the known length that `put()` requires, so the tee rides in the pump instead. Multipart path: `file.slice(0, 64 KB).arrayBuffer()`. After the original is stored, parsed bytes win; the `?width=&height=` hint (positive integers ≤ 65535) fills in only when parsing fails; the INSERT includes the columns only when `hasColumn(photos, width)` (per-isolate cache, as elsewhere). Returned as `width`/`height` on every guest and crew photo object (`dimensions()` normalises to integers or `{ null, null }`).
- **Migration 0013 · events + stats.** `events(id, kind CHECK IN (search, match, zero_match, checkout, paid, download), session_id → sessions ON DELETE CASCADE, search_id → searches ON DELETE SET NULL, created_at)` + index on `(session_id, kind)`; deleting a session takes its events with it (verified on real SQLite). `recordEvents()` inserts one or a batch, catches everything and `console.warn`s with "migration 0013". Recorded: `search` + `match`/`zero_match` right after the search row insert in `/api/match`; `checkout` after the payments insert; `paid` once — verify's `UPDATE payments SET status='verified' … WHERE id = ? AND status NOT IN ('verified','captured')` and the webhook's first of two guarded UPDATEs (`… status NOT IN ('verified','captured')` = the capture transition; the second only upgrades `verified → captured`, keeps `paid_at`, stores `cashfree_payment_id`, records nothing) — the row's `meta.changes` decides, so verify-then-webhook, webhook-then-verify and a replayed webhook all yield exactly one `paid`; `download` in the media route for `variant=original&download=1` (`search_id` null: media tokens carry no search id) and once per ZIP. `GET /api/admin/stats` (admin) → `{ sessions: [{ sessionId, title, searches, matches, zeroMatches, zeroMatchRate, checkouts, unlocks, downloads, rupees }], totals: {…} }` from one `env.DB.batch` of two SELECTs (`sessions LEFT JOIN events … GROUP BY s.id ORDER BY s.created_at DESC`; `payments JOIN searches WHERE p.status IN ('verified','captured') GROUP BY session`). `zeroMatchRate = zeroMatches / searches` (0 when none), `unlocks` = `paid` events, `rupees = round(paise) / 100` (so ≤ 2 decimals), totals summed over the listed sessions. A "no such table" failure → 200 `{ sessions: [], totals: zeros, unmigrated: true }` with a warning; any other D1 failure → 500. **Note on "captured":** `rupees` counts `status IN ('verified', 'captured')` — the guest's `/api/payment/verify` path marks a Cashfree-`PAID` order `verified` and the webhook marks it `captured`; both are money Cashfree confirmed, and a payment whose webhook never arrives would otherwise be invisible.
- **F30 · `POST /api/admin/undo-review`.** Body `{ kind: 'pair' | 'link', id }` (else 400). Reads the row (404 when unknown); `pending` or `updated_at` older than 10 minutes → 409 `Too late to undo — the queue moved on.`; `UPDATE … SET status = 'pending', updated_at = CURRENT_TIMESTAMP WHERE id = ? AND status = <read status>` (0 changes → 409, so a concurrent decision cannot be clobbered); then `removeFeedback()`: `DELETE FROM match_feedback WHERE subject_id = ?` when the column exists and that removed a row, otherwise the newest row with the same `source`, score column (`face_similarity` / `burst_score` / `appearance_similarity`) and `label` from the last 10 minutes (`AND subject_id IS NULL` once the column exists, so tagged rows of other decisions are never touched). Response `{ success: true, kind, id, status: 'pending' }`. `confirm-match`/`confirm-link` now go through `recordFeedback()`, which sets `subject_id` when the column exists (same statements as before otherwise).
- **Health.** `migrations` gains `photoDimensions` (fresh `PRAGMA table_info(photos)`, not the per-isolate cache, so the pill flips the moment the migration lands) and `events` (sqlite_master). W2-A/W2-D: the admin pill can show four flags now.
